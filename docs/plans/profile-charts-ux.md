## Сущности

### Основная карта

- alias: primary chart, `isPrimary: true` на `ChartResult`
- поля: как у обычной карты + `isPrimary`
- связь: User → Client → ChartResult; у user не больше одной primary
- что хранить: флаг на результате; ДР профиля = `User.birthPreferences`
- открытый вопрос: нет

### Пересчитать

- сущность: действие после смены ДР профиля
- что хранить: новая ChartResult (`isPrimary`); у старой `isPrimary: false`
- не путать с «Обновить описание» (`/reinterpret`)

## UI-правила

1. Меню: Моя карта → `/`; Мои карты → `/charts`; Выйти.
2. Профиль: просмотр (имя, email, ДР) + «Редактировать»; без текста «Предпочитаемые данные рождения».
3. Нет primary → «Построить карту» (asPrimary).

7. Удаление: confirm в списке и на странице карты; удалили primary → на `/` форма постройки.

## Уточнение интерфейса: «Моя карта»

- Пункт меню и заголовок `/` — «Моя карта».
- Email находится внутри карточки данных пользователя и остаётся видимым при редактировании. Отдельной строки email над карточкой нет.
- У основной карты нет кнопки удаления: ни на главной, ни на отдельной странице карты, ни в списке «Мои карты». Удаление обычных карт остаётся. Серверный DELETE API этой UI-правкой не меняется.
- Таблицы «Планеты» и «Дома» по отдельности раскрываются и сворачиваются стандартным `details/summary`; изначально свёрнуты. Данные сохраняются без изменений.
- Промпт натальной расшифровки не меняется: `lib/ai/prompts/chart-interpretation.md`, загружается `loadChartInterpretationPrompt` и отправляется как system-сообщение. User-сообщение — текст планет, ASC/MC, домов и распределения планет по домам. Отдельный список натальных аспектов сейчас в этот контекст не передаётся.

## Натальная расшифровка: повторы и абзацы

После полного описания больше не выводить блок `highlights`: прежний код формировал его из первых строк того же ответа ИИ и тем самым повторял ASC и начало описания. Для новых интерпретаций возвращать пустой массив highlights, сохраняя совместимость формата API. Старые highlights не показывать и не включать в скачиваемый Markdown; удалять данные из БД не требуется.

В промпте первичной и повторной интерпретации каждая планета в доме описывается отдельным абзацем, начинающимся с названия планеты. Между описанием дома и каждой планетой — пустая строка Markdown. Версия промпта: `v2-planet-paragraphs`. Старые сохранённые описания автоматически не перегенерировать: новое оформление применяется при создании или обновлении описания.

## Обезличенная натальная расшифровка

Версия промпта `v3-neutral-variants`: без обращения «вы/ваш» и категоричных характеристик личности. Для ASC, оси узлов и Солнца — по 3–5 коротких возможных проявлений; для каждой планеты в доме — 2–3. Дом описывается одним коротким предложением, каждая планета — отдельным абзацем после пустой строки. Варианты альтернативны, не обязательны и не должны приписываться человеку одновременно. Прежние требования длинных психологических портретов и 3–5 предложений на планету заменены этим форматом.

История сохраняется в обоих разделах: `ChartResult.messages` для натальной карты и `Overlay.messages` для затмений. Вопрос и ответ записываются после успешного ответа ИИ; в натальном pipeline добавление пары явно оформлено через `$push/$each`. При ошибке до сохранения неуспешный запрос отдельной записью не хранится. Полный пересчёт основной карты создаёт новую карту с новым чатом; старая переписка остаётся у прежней карты в «Мои карты». Обновление только описания не удаляет чат. При смене версии контекста затмения прежняя переписка архивируется.


## Размещение добавления карты

Кнопка «Добавить карту» доступна в «Мои карты». На главной странице «Моя карта» её нет; там остаются данные пользователя и создание/пересчёт основной карты.
