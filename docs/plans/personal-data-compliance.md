# ПДн, домен, РФ‑хостинг, сброс пароля

Статус: план шагов (спека). Код — только после «делай». Merge/deploy — только по отдельному поручению.

Оператор: физлицо, самозанятый (НПД), РФ. Аудитория: друзья + открытый Telegram‑канал. Сервер сейчас не в РФ — перенос на РФ‑VPS согласован.

Это не юрконсультация. Решение по уведомлению РКН — отдельно, после согласования ниже.

## Что уже сделано

1. Аккаунт: email, passwordHash, имя, birthPreferences.
2. Карты/чаты в Mongo; HTTPS на текущем VPS (не РФ).
3. Минимизация сессий/снимков/чатов (`storage-minimization.md`) — не освобождает от 152‑ФЗ.
4. DaData/Nominatim: в запрос уходит строка поиска города (не email/ДР профиля).
5. Astrology API: уходит дата/время/координаты для расчёта.
6. ИИ: целевой режим — только планеты/дома; **факт:** в чате (`ask`) ещё может уходить `birthInput` — закрыть отдельным шагом.

## Что осталось

1. Домен + РФ‑VPS (app + Mongo) + HTTPS.
2. Политика ПДн + согласие на регистрации (минимум идентификации оператора).
3. Решение по уведомлению РКН (открытый вопрос).

5. Удаление аккаунта целиком.
6. Убрать ДР из промптов ИИ (оставить планеты/дома).
7. Обновить `deployment.md` под РФ‑хост и домен.

## Минимум «светить» оператора в политике

Публиковать не нужно: паспорт, ИНН, домашний адрес, телефон.

Минимум для субъекта ПДн:

1. Название сервиса (бренд).
2. Статус: физлицо / самозанятый.
3. Рабочий email для запросов по ПДн (можно `privacy@домен` или отдельный ящик).
4. Цели обработки, состав данных, сроки, третьи лица, как удалить данные.

ФИО в публичном тексте — по желанию; если юрист потребует однозначную идентификацию оператора — добавить ФИО без адреса. **Открытый вопрос:** бренд+email достаточно или нужно ФИО в политике.

## Домен (предложение)

Пока кандидата нет. Предлагаемый минимум:

1. Зона: `.ru` (проще для РФ‑сервиса и почты).
2. Короткие варианты: `natalru.ru`, `mynatal.ru`, `astrokart.ru`, `natalkarta.ru`.
3. Пока домен не куплен — в деплое/политике плейсхолдер `https://<domain>`.

**Открытый вопрос:** какой домен покупаем.

## Почта для писем (предложение)

1. Предпочтительно: ящик на своём домене (`noreply@…`, `privacy@…`) через Yandex 360 / VK Workspace / Mail.ru для бизнеса.
2. В письме сброса: только ссылка/код, без ДР и карт.
3. Не использовать личный Gmail как From в проде (спам + путаница с оператором).

**Открытый вопрос:** провайдер почты после покупки домена.

## Уведомление РКН

1. Желание «не светить» понятно; открытый канал + аккаунты + Astrology API = обработка ПДн с передачей третьему лицу.
2. Исключение «только договор без передачи третьим» — под вопросом из‑за Astrology API (и ИИ, пока уходит контекст карты).
3. DaData с одной строкой города — слабее как передача ПДн профиля, но не отменяет оператора по своей БД.

**Решение пока отложено.** Варианты после этого обсуждения:

- A: подать уведомление (безопаснее при публичном канале).
- B: не подавать после письменного заключения юриста по вашим потокам.
- C: сначала закрыть техшаги (РФ, политика, убрать ДР из ИИ), затем выбрать A/B.

Согласовать A/B/C до любых действий в РКН.

## Итерации (порядок шагов)

### Шаг 1 — орг
1. Выбрать домен из списка (или свой).
2. Купить домен + РФ‑VPS (достаточно app+Mongo; RAM ориентир как сейчас ≥2 ГБ).
3. Завести почту на домене (или отложить до шага 5, если сброс пароля позже).
4. Зафиксировать A/B/C по РКН.

### Шаг 2 — тексты
1. Политика ПДн (бренд, контакт, цели, Mongo, Astrology API, ИИ без ДР, DaData‑поиск города, почта).
2. Текст согласия на регистрации.
3. Страница `/privacy` (или аналог) + ссылка в футере/регистрации.

### Шаг 3 — инфра
1. Перенести деплой на РФ‑VPS; Mongo только там.
2. HTTPS на домене; выключить старый не‑РФ сервер после проверки.
3. Обновить секреты CI / `deployment.md` (хост, URL).

### Шаг 4 — продукт: согласие и удаление
1. Чекбокс согласия при регистрации (без галки — нет аккаунта).
2. Удаление аккаунта: User + карты + наложения + связанные записи.

### Шаг 5 — продукт: сброс пароля
1. Запрос email → одноразовый токен → письмо → новый пароль.
2. Rate limit / срок жизни токена.

### Шаг 6 — минимизация для ИИ
1. Убрать `birthInput` из промптов чата/интерпретаций; оставить планеты, дома, аспекты.
2. Проверить логи/Langfuse: нет email/ДР в трассировках (если Langfuse снова включат).

### Шаг 7 — опционально после A/B
1. Если A — подать уведомление РКН по факту после шагов 2–3.
2. Если B — сохранить заключение юриста вне репо (не коммитить ПДн оператора).
