## Auth: Telegram + изменения входа (зафиксировано, не в этом PR)

### Сущность User (цель)

- `telegramId` — optional, unique sparse.
- `email` — optional, unique sparse.
- `passwordHash` — optional.
- Нужен хотя бы `telegramId` или `email`.
- Имя / birthPreferences — как сейчас.
- Миграция: текущие email+пароль остаются валидны; пароль — опция, не требование.

### Связь способов

1. Telegram Login Widget → проверка подписи → найти/создать User → JWT.
2. Email → OTP на почту → сессия (SMTP на шаге 8; до этого — закладка API).
3. В профиле: «Привязать Telegram» / «Привязать email» к текущему User.
4. Конфликт id/email у другого User — ошибка, без автослияния.
5. Согласие с `/privacy` при первом создании через TG или email.

### Почему не только код на почту

Сбои/спам почты → «не входят». Telegram из канала компенсирует. Оба способа на одном аккаунте — целевая схема.

### Порядок реализации auth (когда скажете «делай»)

1. Шаг 2 — схема User.
2. Шаг 3 — Telegram Login (`BOT_TOKEN`, domain/`APP_BASE_URL`).
3. Шаг 4 — email OTP + привязки; пароль оставить опцией для старых.

## РФ‑VPS: минимум по сложности

Ориентир как текущий prod (~2 ГБ, без Langfuse).

| Параметр | Минимум | Комфортнее |
|----------|---------|------------|
| RAM | **2 ГБ** | 4 ГБ |
| vCPU | 1–2 | 2 |
| Диск | 20–40 ГБ SSD | 40 ГБ |
| ОС | Ubuntu 22.04 | то же |
| Состав | Docker: app + Mongo 7 | то же |
| Сеть | публичный IPv4 | + домен позже |

1. Не брать 1 ГБ — Mongo + Next часто упираются.
2. Langfuse на этом тарифе не поднимать.
3. Сборка образа — в CI (как сейчас), на VPS только `pull` + compose.
4. Провайдеры РФ (на выбор): Timeweb, Selectel, Reg.ru VPS, Beget — регион РФ обязателен для локализации ПДн.
5. Сложность переноса: скопировать `.env`, `docker-compose.prod.yml`, том/дамп Mongo, nginx+HTTPS; обновить `PROD_SSH_*` в GitHub Secrets.
