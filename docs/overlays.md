# Наложения

Реализованы страница `/overlays`, сохранённые результаты `/overlays/[id]`, каталог затмений, пять типов аспектов, расшифровка и отдельный чат результата. Требования: [спецификация](./plans/eclipse-overlays.md).

## Начальное заполнение после установки версии

1. Войти в приложение, открыть меню пользователя → «Наложения».
2. В разделе каталога нажать «Загрузить каталог 2026–2027». В БД идемпотентно сохраняются девять событий; повторное нажатие не создаёт дубликаты. На этом шаге нет вызовов Astrology API или ИИ.
3. Нажать «Подготовить все карты» либо готовить события по одному. Для каждого ещё не рассчитанного события один раз запрашиваются реальные положения планет и сохраняются в MongoDB. Готовые карты повторно не запрашиваются. Нужны `ASTROLOGY_API_KEY` (или существующий `API_KEY`), `ASTROLOGY_USE_MOCK` не должен быть `true`, `AI_PROVIDER` не должен быть `mock`. Фиксированные моки 1984 года для каталога запрещены.
4. Нажать «Новое наложение», выбрать свою карту и затмение. Если карта затмения ещё не подготовлена, она рассчитывается на этом шаге.
5. Сначала сохраняются снимки карт и аспекты; затем на странице результата отдельным POST автоматически запрашивается первая расшифровка. При ошибке её можно повторить кнопкой. Существующая пара открывает сохранённый результат, без новых расчётов и автоматических вызовов ИИ.

GET-запросы ничего не заполняют и не вызывают Astrology API. Чат и обновление расшифровки используют только сохранённые данные. Все операции требуют сессию; результаты и чаты доступны только владельцу.

Загрузка каталога и заполнение production-БД в рамках подготовки PR не выполнялись. Merge и deploy не выполнялись.

## Источник и время

Eclipse Predictions by Fred Espenak (NASA's GSFC):
- [События 2026](https://eclipse.gsfc.nasa.gov/OH/OH2026.html).
- [События 2027](https://eclipse.gsfc.nasa.gov/OH/OH2027.html).

Используется столбец Greatest Eclipse (TD), с точностью исходной таблицы до секунды. Это максимум затмения, не точный момент новолуния/полнолуния.

Для каталога TD/TT переведено в UTC по `TT − UTC = 32.184 + (TAI − UTC) = 69.184 с`, результат округлён до целой секунды, которую поддерживает Astrology API. Использование `TAI − UTC = 37 с` для будущих событий — явное предположение об отсутствии новых leap seconds. Прогнозный столбец NASA Delta T описывает `TT − UT1`, поэтому он не использован как `TT − UTC`. Исходное TD, URL, точность и пояснение преобразования сохраняются в БД. При объявлении новой leap second будущие даты нужно сверить до первоначальной загрузки; редактирования сохранённых событий в UI нет.

## Хранение и обработка ошибок

`Eclipse` содержит исходный ответ Astrology API и абсолютные долготы 12 тел (Солнце–Плутон, средний Северный узел и противоположный Южный). Общие карты затмений повторно используются разными пользователями.

`Overlay` содержит снимки исходных данных, аспекты, расшифровку, сообщения и владельца. Уникальный индекс по владельцу, двум картам и версии расчёта предотвращает дубликаты. Снимки не исчезают при удалении исходной натальной карты.

Внешние операции защищены атомарными MongoDB-блокировками с токеном и сроком 5 минут. Вызов Astrology API ограничен 60 секундами, ожидание ИИ — 120 секундами. При параллельном расчёте второй клиент получает 409 и может повторить запрос позже. Неудачные/прерванные операции можно повторять после освобождения/истечения блокировки. Вызов провайдера ИИ после локального таймаута может ещё завершаться у провайдера; поздний ответ в БД не записывается.

Повторное получение положений требуется только если корректный результат ещё не сохранён (ошибка API/валидации/записи или прерванный процесс). Успешно сохранённые положения не перезапрашиваются.

ИИ получает текущую расшифровку как пересматриваемый предыдущий ответ и последние 20 сообщений с контекстом выбранных аспектов. В БД сохраняется вся переписка. Обновление расшифровки не получает старый текст, а сбой обновления не удаляет предыдущий успешный ответ.

## Проверка этой поставки

Проведено ревью путей авторизации, сохранения и повторного использования данных, атомарных блокировок и поведения при ошибках. Без зависимостей выполнены проверки математики пяти аспектов, границ 5°, перехода 359°→2°, узлов, сортировки, неполных/некорректных данных и каталога из девяти событий. Проверен синтаксис новых серверных TypeScript-файлов и `git diff --check`.

По указанию пользователя установка зависимостей, проверка типов и сборка не выполнялись после остановки попытки установки. Работа UI, MongoDB и реальные вызовы Astrology/ИИ в этой среде не проверены. Нужна проверка приложения перед merge/deploy; этот PR не запускает деплой.
